# Contributing to StainlessSteel

Thank you for your interest in StainlessSteel. The first-party application is **source-available under PolyForm Strict 1.0.0**, which does **not** automatically authorize modifications or distributions. Do not assume ordinary open-source fork-and-PR permissions.

## Public participation

Issues, feature proposals, test reports, security reports and high-level design discussions are welcome. Do not post private credentials, proprietary code, secret logs or unpublished vulnerabilities in public issues.

## Code contributions: invitation-only until legal setup is complete

Before modifying original StainlessSteel source for a contribution or submitting a patch, request **written contributor development permission** and complete the maintainer's contributor agreement. Maintainers will provide the authorized workflow and scope. Until that happens, PRs are not accepted as licensed code contributions.

The future contributor agreement must be reviewed by counsel and must clearly address: ownership of authored code; a nonexclusive, irrevocable right for maintainers to use, adapt, distribute and license accepted contributions commercially and under other licenses; contributor representations; patent rights; employer/third-party approvals; attribution and retention of ownership if that model is chosen. Do not claim a CLA is effective until each contributor signs it.

**Never copy GPL/AGPL code, unlicensed snippets, other vendors' private code, or code from a project with incompatible obligations into StainlessSteel.** Upstream bug fixes must comply with upstream rules.

Public GitHub **forking within GitHub** is separately allowed by GitHub's platform terms. It should not be confused with a blanket permission to modify, republish or distribute StainlessSteel.

## Maintainer-only setup checklist

- [ ] Agree upon legal rightsholder and business contact.
- [ ] Have counsel approve the contributor agreement and permissions process.
- [ ] Record contributor permissions, agreement version and signatures privately.
- [ ] Require provenance checks and license scans for all incoming code.
- [ ] Review every accepted contribution for third-party code and trade secrets.
