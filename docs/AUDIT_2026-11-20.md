# Audit report — 20 November 2026

Scope: full source tree at `main` (single-crate CLI: `src/main.rs`, `model.rs`,
`store.rs`, `tui.rs`, `update.rs`; 12 integration tests), `Cargo.toml` /
`Cargo.lock`, licensing documents, and public docs. Method: line-by-line code
read, locked test suite, `cargo fmt --check`, `cargo clippy -- -D warnings`,
release build, OSV advisory scan of every direct and newly added transitive
dependency, license-text diff against the upstream PolyForm repository, and
detection test with the same engine GitHub uses (licensee 10.1.0).

## Verdict

No blocking defects. One latent TLS gap was found and fixed during this
audit (see §3). The tree is green: fmt clean, Clippy with `-D warnings`
clean, 12/12 tests pass, release build succeeds.

## 1. Code

- **Session journal (`store.rs`).** WAL + `synchronous=FULL`, bounded writer
  via `Immediate` transactions, `one_active` guard against concurrent turns,
  schema versioning with forward-migration refusal, `VACUUM INTO` temp-file
  snapshots with `integrity_check` verification and never-overwrite publish.
  Foreign keys enforced, so events cannot reference ghost sessions. Sound.
- **Model transport (`model.rs`).** Loopback-only (`127.0.0.1`, port is data
  not a URL), redirects disabled, proxy disabled, 5 s connect / 180 s total
  timeouts, 1 MiB reply cap with 16 MiB stream cap, `[DONE]` framing enforced,
  interrupted turns marked (never silently retried). `max_tokens: 1024` is
  hard-coded — per-model budgets belong to the provider-routing workstream.
- **TUI (`tui.rs`).** Alternate screen with `Drop`-based restore, event-driven
  redraw (idle-quiet), worker thread opens its own SQLite connection, model
  keystrokes never logged. Draft input capped at the same 64 KiB as the CLI.
- **Update channel (`update.rs`, new).** Version comparison is numeric per
  segment; failures are explicit errors, never silent. No code is downloaded
  or executed — check is read-only by construction.
- **Minor notes (non-blocking).** `backup()` surfaces a cleanup error instead
  of the original failure if temp-file removal also fails; `rename` writes a
  `renamed` event even when the name is unchanged. Neither loses data.

## 3. Findings fixed in this cycle

- **`update check` could not reach HTTPS.** `ureq` was built with
  `default-features = false` (correct for the plaintext loopback model
  client), which also removed its TLS stack. Fixed by adding the `tls`
  feature; the model path is unchanged and still proxy-free. Verified live:
  `update check` reports `Already up to date (v0.1.0)` with matching JSON.
- **Install receipt added.** `install.sh` now writes
  `.stainless-install-receipt.json` beside the binary; `update status`
  reports `direct` with receipt contents, otherwise `unknown`. Round-trip
  verified: installed receipt → `install: direct`.

## 4. Licensing

- `LICENSE` (extensionless, for monospace GitHub rendering) is byte-identical
  to the kit text except one line: ours reads "licenses granted to you **under**
  these terms"; the current upstream file reads "**for the software under**
  these terms". Substance is unaffected, but the compliance policy calls for
  unchanged official text — alignment is one accepted follow-up.
- Verified with licensee 10.1.0 (GitHub's own detector): PolyForm Strict is
  **not in its database**, so no PolyForm text can earn a named license tab.
  Confirmed against the official upstream file too — same `NOASSERTION`.
  The generic "License" tab plus the in-repo license chain
  (`LICENSE` → scope → commercial → contributing) is the correct presentation;
  switching to a detected license (e.g. MIT) would permit commercialization
  and contradict the project goal.
- Placeholders filled: copyright holder, permission contact (Issues),
  vulnerability channel (Security Advisories). No `[RIGHTSHOLDER]` /
  `[INSERT …]` markers remain in first-party docs.
